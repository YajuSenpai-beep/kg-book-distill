# 图算法与图数据分析

补充模块，对应原书“图算法与图数据分析”一章。用于回答：**什么时候该用图算法/图神经网络，而不是继续用查询或规则？**

---

## 1. 适用边界

适合：
- 需要节点重要性、社区结构、路径、子图相似度。
- 需要节点分类、链接预测、图级分类。
- 知识图谱图结构较丰富，邻居信息对任务有增益。
- 需要可解释的路径/子图证据。

不适合：
- 简单点查、属性过滤、聚合统计（用图库/关系库查询即可）。
- 图谱高度稀疏、大量孤立节点（GNN 难以聚合有效信息）。
- 任务主要依赖语义/逻辑，而不是图结构。
- 没有节点特征，且图结构本身噪声很大。

**先做结构体检**：

| 指标 | 用途 | 经验判断 |
|---|---|---|
| 节点数 / 边数 | 规模 | 决定单机/分布式 |
| 平均度 | 稀疏性 | 平均度 < 2 时慎用 GNN |
| 最大连通分量占比 | 连通性 | 占比低说明图碎片化 |
| 度分布 | 是否无尺度 | 长尾明显时注意头部主导 |
| 同配性/同质性 | 邻居是否同类 | 低同质性时 GNN 增益有限 |
| 节点特征覆盖率 | 特征可用性 | 缺失高时先补特征或改用结构方法 |

这些是启发式，不是定律；最终以任务验证为准。

## 2. 图的基础概念

| 概念 | 含义 | 工程用途 |
|---|---|---|
| 度 degree | 节点边数；有向图分入度/出度 | 发现枢纽、过滤噪声 |
| 度分布 P(k) | 随机节点度为 k 的概率 | 判断无尺度/随机网络 |
| 邻接矩阵 A | Aij 表示 i,j 是否有边 | 图算法与 GNN 输入 |
| 二部图 | 节点分两组，边只跨组 | 用户-物品、作者-论文 |
| 最短路径 | 两节点间最短路径 | 关系距离、路径解释 |
| 直径 | 所有节点对最短路径的最大值 | 图的可达性 |
| 平均路径长度 | 所有节点对最短路径均值 | 小世界特性 |
| 环 cycle | 起点终点相同的路径 | 发现循环依赖/欺诈环 |
| 自回避路径 | 不重复经过节点的路径 | 路径枚举 |
| 欧拉路径 | 经过每条边一次 | 图论基础，少用于 KG |
| 汉密尔顿路径 | 经过每个节点一次 | 图论基础，少用于 KG |
| 聚集系数 | 邻居之间相互连接的程度 | 社区紧密程度 |

**常见图模型**：
- 六度理论：社交网络中短路径普遍存在。
- 弱联系：信息常通过弱关系传播。
- 无尺度网络：优先连接导致幂律度分布，少数枢纽节点拥有大量连接。
- 随机网络：Erdos-Renyi 模型，度分布近似二项/泊松；用于对照“随机基线”。

知识图谱与普通图的区别：节点和边有类型、有语义、异质、可能有属性；图算法通常需要先做类型过滤或投影。

## 3. 传统图算法

### 3.1 路径与搜索

| 算法/问题 | 作用 | 复杂度/注意 |
|---|---|---|
| BFS/DFS | 遍历、连通性、最短跳数 | 无权图；BFS 求最少跳数 |
| Dijkstra | 单源最短加权路径 | 非负权重；可用堆优化 |
| 单源/全源最短路径 | 一个/所有节点对 | 全源在大图上昂贵 |
| 最小生成树（Kruskal/Prim） | 连通所有节点的最小代价 | 无向连通图；不适合有向语义图 |
| 子图匹配 | 查询模式匹配 | NP 难，需限制模式大小 |

工程建议：多跳查询先限制跳数（2–3）与候选集，再做精确匹配；不要在全图上做无界路径枚举。

### 3.2 中心度

| 算法 | 衡量 | 适用 | 注意 |
|---|---|---|---|
| 度中心度 | 直接连接数 | 找活跃节点 | 头部节点可能只是噪声 |
| 中介中心度 | 经过该节点的最短路径数 | 找桥梁/瓶颈 | 计算贵，大图需近似 |
| 接近中心度 | 到其他节点的平均距离 | 找传播最快节点 | 不连通图需处理 |
| PageRank | 邻居重要性递归加权 | 找权威节点 | 有向图；需处理悬挂节点 |

中心度是“结构重要性”，不等于“业务重要性”；必须用下游任务验证。

### 3.3 社区发现

| 方法 | 作用 | 注意 |
|---|---|---|
| 强连通分量 | 有向图互相可达的节点组 | 适合依赖/引用环 |
| 弱连通分量 | 无向可达的节点组 | 并查集实现 |
| 标签传播 LPA | 快速社区划分 | 结果不稳定，需多次运行 |
| Louvain/模块度 | 优化社区紧密程度 | 分辨率限制；大图常用 |
| 三角计数/聚集系数 | 局部紧密程度 | 可用于欺诈环/异常检测 |

社区结果不是“ ground truth”，要结合业务解释与稳定性评估。

### 3.4 按问题选算法

| 问题 | 首选 | 备选 |
|---|---|---|
| 两实体之间有没有路径/多远 | BFS/Dijkstra | 图库最短路径 |
| 谁是关键节点/瓶颈 | PageRank/中介中心度 | 度中心度 |
| 有哪些团伙/社群 | Louvain/标签传播 | 连通分量 |
| 是否存在循环依赖/欺诈环 | 环检测/强连通分量 | 三角计数 |
| 两个子图是否相似 | 子图匹配/图核 | 图嵌入相似度 |

## 4. 图表示学习

目标：把节点映射为低维向量，使结构与语义相似性可计算。

| 模型 | 核心思想 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| DeepWalk | 随机游走 + Skip-gram | 简单、可扩展 | 只捕获邻近性 | 同构图、无特征 |
| Node2Vec | 有偏随机游走（BFS/DFS，p/q） | 兼顾同质性与结构相似 | 需调 p/q | 同构图 |
| LINE | 一阶/二阶相似度 | 支持有向/加权图 | 只到二阶 | 大图、稀疏 |
| NetMF | 矩阵分解统一框架 | 理论清晰 | 矩阵分解成本 | 中小图 |
| Metapath2Vec | 元路径随机游走 | 处理异构图语义 | 需定义元路径 | 学术/电商等异构图 |

关键参数：
- 游走长度、每节点游走次数、窗口大小、维度。
- Node2Vec 的 p（返回）与 q（进出）：q>1 偏 BFS（同质），q<1 偏 DFS（结构）。
- 元路径决定语义，如“作者-论文-作者”表示合作者关系。

适用判断：没有节点特征、图较大、只做节点相似/聚类/链接预测时，先跑随机游走基线。

## 5. 图神经网络

### 5.1 基本机制

消息传递：每个节点聚合邻居表示，再与自己表示融合，多层堆叠扩大感受野。

两类设定：
- **直推式 transductive**：训练时见过测试节点/边；效果通常更好，但不能泛化到新节点。
- **归纳式 inductive**：测试新节点/子图；泛化更好，工程上更常用。

### 5.2 模型谱系

| 模型 | 核心 | 设定 | 适用 | 注意 |
|---|---|---|---|---|
| GCN | 归一化邻居聚合 | 直推为主 | 半监督节点分类 | 需固定邻接，难以扩展到新节点 |
| GraphSAGE | 邻居采样 + 聚合函数 | 归纳 | 大图、新节点 | 采样带来方差 |
| GAT | 邻居注意力加权 | 直推/归纳 | 邻居重要性不同 | 多头、内存开销 |
| VGAE | 编码器-解码器，重建邻接 | 无监督 | 节点表示、链接预测 | 重建目标偏结构 |
| DiffPool | 层次化池化 | 图级任务 | 图分类 | 池化矩阵成本高 |
| GPT-GNN | 生成式预训练（属性+结构） | 预训练+微调 | 大规模图、标签少 | 训练成本 |
| GCC | 对比学习（子图正负样本） | 预训练 | 跨图结构预训练 | 需构造子图样本 |

### 5.3 选择表

| 条件 | 选择 |
|---|---|
| 大图、需要泛化到新节点 | GraphSAGE / GAT |
| 固定图、半监督节点分类 | GCN |
| 无标签、学节点表示 | VGAE / 随机游走 |
| 图级分类 | DiffPool 等层次模型 |
| 标签稀缺、可预训练 | GPT-GNN / GCC |
| 邻居重要性差异大 | GAT |
| 极大规模、单机放不下 | 采样 + 分布式 / 先做图分区 |

## 6. 知识图谱与图神经网络

### 6.1 知识图谱表示学习 vs 图表示学习

| 维度 | KRL（TransE 等） | 图表示学习/GNN |
|---|---|---|
| 关注 | 三元组语义、关系类型 | 图结构、邻居 |
| 监督 | 三元组正负样本 | 节点标签/结构/自监督 |
| 输出 | 实体与关系向量 | 节点/子图向量 |
| 强项 | 链接预测、关系推理 | 节点分类、社区、图级任务 |
| 弱项 | 图结构利用不足 | 关系语义与逻辑弱 |

### 6.2 常见组合

| 模型 | 做法 | 用途 |
|---|---|---|
| R-GCN | 按关系类型分别聚合邻居，参数可基分解/对角分解 | 实体分类、链接预测 |
| CompGCN | 实体与关系组合，按入/出/自连接区分 | 同时学实体与关系表示 |
| ExpressGNN | GNN 加速马尔可夫逻辑网络推理 | 概率图推理 |
| RDGCN | 主图 + 关系对偶图，注意力交互 | 实体对齐 |

**典型架构**：GNN 编码器 + KGE 解码器（TransE/DistMult）做链接预测；或 GNN 输出 + 分类层做实体分类。

### 6.3 适用性检查

- 平均度是否足够？邻居是否有信息？
- 边类型是否重要？需要 R-GCN/CompGCN 而不是普通 GCN。
- 是否需要泛化到新实体？需要 GraphSAGE/GAT 类归纳模型。
- 是否稀疏？稀疏图上 GNN 通常不如 KRL + 外部信息（DKRL/PTransE）。
- 是否要求可解释？GNN 的注意力/子图可提供部分解释，但不如规则/路径直接。

## 7. 图算法在 KG 工程中的用法

| 任务 | 方法 | 产出 |
|---|---|---|
| 图谱治理 | 度/中心度/连通分量 | 关键实体、孤立子图、噪声簇 |
| 领域划分 | 社区发现 | 子领域/业务域 |
| 可解释推理 | 最短路径/子图 | 关系路径证据 |
| 实体对齐分块 | 邻居/结构相似度 | 候选对 |
| 类型补全 | 节点分类 | 缺失类型 |
| 链接预测 | GNN/KRL | 候选关系 |
| 异常检测 | 环/三角/密集子图 | 可疑团伙/循环 |
| 推荐 | 图嵌入/图神经网络 | 用户/物品表示 |

## 8. 选型决策树

```
任务是否真的需要图结构？
├─ 否 → 用查询/规则/表格
└─ 是 → 图是否足够稠密（平均度、连通分量）？
         ├─ 否 → 先用 KRL/规则/外部信息，GNN 只做辅助
         └─ 是 → 是否需要泛化到新节点？
                  ├─ 是 → GraphSAGE/GAT/归纳式
                  └─ 否 → GCN/VGAE/随机游走
                           ↓
                  是否有节点/边特征？
                  ├─ 是 → GNN
                  └─ 否 → 随机游走/矩阵分解/结构特征
                           ↓
                  是否要求强可解释？
                  ├─ 是 → 路径/规则/中心度 + 人工审核
                  └─ 否 → GNN/KRL
```

## 9. 评测

| 任务 | 指标 | 注意 |
|---|---|---|
| 节点分类 | Accuracy/F1 | 直推/归纳分开报告 |
| 链接预测 | AUC/AP/Hit@n/MRR | 负采样口径一致；时间切分防泄漏 |
| 图分类 | Accuracy/F1 | 图级切分，避免同源泄漏 |
| 社区发现 | 模块度/NMI（有标签时） | 稳定性：多次运行 |
| 中心度 | 下游任务收益/稳定性 | 不要只报分数 |
| 效率 | 预处理、内存、推理延迟 | 大图必须报告 |

## 10. 反模式

1. 在稀疏 KG 上直接上 GNN，然后归因于“模型不行”。
2. 忽略边方向与类型，把 KG 当无向同构图。
3. 随机切分导致节点/边泄漏，指标虚高。
4. 拿直推式结果宣称归纳能力。
5. 把中心度当业务重要性，不做任务验证。
6. 把社区发现结果当唯一真相。
7. 不做随机基线（度/PageRank/随机游走）就直接上复杂模型。
8. 图算法结果没有业务解释就上线。

## 11. 最小落地清单

- [ ] 图结构体检（规模、平均度、连通分量、度分布、特征覆盖率）。
- [ ] 任务定义与切分方式（直推/归纳、时间切分）。
- [ ] 基线：度中心度/PageRank/随机游走/简单 GCN。
- [ ] 复杂模型只在基线有明确缺口时引入。
- [ ] 报告结构指标与任务指标，而非只报模型分数。
- [ ] 对高风险结果提供路径/子图证据。
