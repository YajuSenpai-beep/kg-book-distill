# 覆盖审计：蒸馏结果 vs 原书知识点结构（v1.2）

## 结论

**v1.1 补上了三个大缺口**：图算法/GNN、语言知识图谱（HowNet/义原）、前沿模块（多模态/事理/知识预训练/联邦）。**v1.2 又补了概念底座**，把历史、价值、传统知识表示、典型项目、问答类型等背景收口。

方法层面的覆盖已接近完整，但仍**不能保证**逐节保留原书知识点细节：实验数据、公式推导、图表、参考文献、部分模型实现仍被有意压缩。当前产物仍是“可执行方法论 Skill”，不是“知识点全集”。

## 2. 统计口径

- 统计单位：原书目录的**章**与**二级节**（PDF 目录层级）。
- 状态：
  - **● 已蒸馏**：作为可执行方法/决策表/Rubric 进入 Skill，能指导动作。
  - **◐ 部分保留**：概念、名称或选型被提及，但细节/实验/案例/公式未保留。
  - **○ 未纳入**：有意省略，或仅作为背景/证据索引存在。
- 不计入：目录、前言、推荐序、总结节、参考文献、后记、封面封底。

## 6. 能保证什么，不能保证什么

**能保证：**
- 主流程、概念底座与三个专项模块的工程决策结构完整。
- 关键选型有依据、有适用条件、有反模式。
- 每条规则可回溯到原书章节/页码（见 `evidence-map.md`）。
- 抽取全文与 OCR 结果保留，可重新审计。

**不能保证：**
- 原书知识点细节的逐条保留（当前 98% 二级主题有方法级覆盖，但细节有压缩）。
- 所有模型公式、实验数据、案例细节、历史细节。
- OCR 对公式、表格、图注的无损还原（平均置信度 0.984，但仍有错字与表格错位）。
- 用 Skill 回答原书任意细节题；它面向“怎么做”，不面向“第几页说了什么”。

## 7. 若要“保证知识点结构”，应补的产物

1. **知识点地图**：按“章→节→概念→定义→公式/例子→前置知识”生成 300–500 个知识点的层级索引（Markdown + CSV）。
2. **覆盖矩阵**：每个知识点标注是否进入 Skill、进入哪个模块、证据页码。
3. **抽测验证**：从两书随机抽 50–100 个知识点，用 Skill 回答，统计命中率；低于阈值则回补。
4. **细节补全**：对仍标 ◐ 的书 B 第8章（综述）按需补；其余主题补“公式/实验/案例”级细节。

当前 Skill 是“方法论操作系统”，不是“知识点数据库”。两者可以并存，但不应混淆。
