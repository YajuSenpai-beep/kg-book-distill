# 前沿与专项模块

补充模块，覆盖原书中的多模态知识图谱、知识增强语言预训练、事理知识图谱、低资源学习、结构化知识预训练、联邦/区块链，以及融合与问答的前沿方法。

使用原则：**先证明增益，再接入；先小流量，再扩量；始终保留非前沿兜底。**

---

## 1. 多模态知识图谱

### 1.1 什么时候值得做

适合：
- 实体有稳定的图像/视频/音频，且视觉信息能补充结构化属性。
- 任务涉及跨模态检索、视觉问答、零样本识别、推荐。
- 实体消歧需要视觉证据（同名人物/地点）。

不适合：
- 图像覆盖率低、质量差、与实体对齐困难。
- 任务只依赖文本/结构化属性。
- 没有多模态编码与存储成本预算。

### 1.2 构建路线

| 步骤 | 做法 | 产出 |
|---|---|---|
| 视觉实体化 | 为图片/视频片段建立可引用实体 | 视觉实体 ID |
| 实体链接 | 视觉实体 ↔ 图谱实体 | sameAs/描述关系 |
| 视觉关系抽取 | 对象检测 + 场景图 | 对象间关系 |
| 多模态属性 | 图像描述、颜色、场景等 | 属性三元组 |
| 质量过滤 | 去重、去不相关、多样性 | 干净多模态子集 |

常见模式：
- 图像作为实体的多值属性（一个实体多张图）。
- 图像实体之间建立视觉相似/相邻关系。
- 图像与文本实体通过 `imageOf` 等关系连接。

### 1.3 融合与推理

- 分别编码结构、文本、图像，再映射到公共空间。
- 多图像用注意力聚合，降低低质量图影响。
- 可用于：多模态链接预测、实体对齐、视觉问答、推荐。
- 风险：模态缺失、噪声、对齐错误会被放大。

### 1.4 评估

- 多模态补全：链接预测指标 + 模态消融。
- 跨模态检索：Recall@k、mAP。
- 视觉问答：准确率 + 知识增益。
- 必须报告“去掉多模态后”的基线，证明增益。

## 2. 知识增强语言预训练

### 2.1 三种注入方式

| 方式 | 做法 | 代表思路 | 适用 | 风险 |
|---|---|---|---|---|
| 实体向量注入 | 实体嵌入作为输入/特征 | ERNIE、KnowBERT | 实体相关任务 | 图谱空间与语言空间对齐难 |
| 预训练任务注入 | 实体掩码/替换、链接预测目标 | WKLM、KEPLER | 有大规模文本+图谱 | 训练成本、噪声 |
| 外部适配器 | 冻结语言模型，只训适配器 | K-Adapter | 持续注入新知识 | 适配器管理与组合 |

### 2.2 什么时候有效

- 低资源任务、低频实体、需要外部事实的任务。
- 图谱覆盖目标领域，实体链接质量高。
- 有足够文本与图谱对齐数据。

什么时候可能有害：
- 图谱噪声大、实体链接错误多。
- 目标任务与图谱领域不匹配。
- 知识注入带来分布偏移，反而降低效果。

### 2.3 知识图谱预训练（PKGM 类）

| 模式 | 做法 | 适用 |
|---|---|---|
| 静态预训练 | 预训练实体/关系向量表，下游按 ID 查询 | 大规模图谱、重复服务 |
| 动态预训练 | 根据下游任务动态编码上下文三元组 | 任务差异大、需要适配 |
| 服务化 | 提供三元组查询/关系查询向量，不暴露原始三元组 | 数据隔离、隐私 |

工程要点：
- 预训练阶段用三元组分类/链接预测自监督。
- 服务阶段输出向量而非原始三元组，便于复用与隔离。
- 下游模型用拼接/池化/注意力融合服务向量。
- 评估：下游任务增益、冷启动实体、困难样本。

## 3. 事理知识图谱（Event Logic Graph）

### 3.1 与实体图谱的区别

| 维度 | 实体知识图谱 | 事理知识图谱 |
|---|---|---|
| 节点 | 实体/概念 | 事件（谓词性短语） |
| 边 | 实体关系 | 顺承/因果/条件/反转/上下位/组成/并发 |
| 知识形态 | 事实 | 事件演化规律 |
| 确定性 | 较确定 | 带概率/置信度 |
| 回答 | Who/What/Where/When | Why/How/下一步 |

### 3.2 事件定义

- 事件用抽象、泛化、语义完备的谓词短语表示。
- 至少包含一个事件触发词；主体/客体可在场景中省略。
- 粒度过细难以泛化，过粗难以理解；需结合场景定义。

### 3.3 关系类型

| 关系 | 含义 | 注意 |
|---|---|---|
| 顺承 | 时间先后 | 边带转移概率 |
| 因果 | 前因后果 | 因果强度；与顺承是子集关系 |
| 条件 | 前提与结论 | “理由”不等于“原因” |
| 反转 | 互斥/真假反转 | 需上下文 |
| 上下位 | 事件分类 | 通常确定性，无需概率 |
| 组成 | 整体与部分 | 事件分解 |
| 并发 | 同时发生 | 时间窗 |

### 3.4 构建与应用

构建：
1. 定义事件 Schema（类型、触发词、论元角色）。
2. 事件抽取（触发词分类 + 论元角色）。
3. 事件关系抽取（规则/分类/远程监督）。
4. 事件链接到实体图谱（实体识别 + 链接）。
5. 概率/置信度估计与人工校验。

应用：
- 事件预测、消费意图识别、新闻重要性判别、对话生成、问答（Why/How）、辅助决策。

风险：
- 事件 Schema 不稳定，关系标注主观。
- 概率估计缺乏校准。
- 与实体图谱融合时粒度不一致。

### 3.5 适用判断

- 任务是否关心“接下来会发生什么/为什么发生”？
- 是否有稳定的事件类型与论元体系？
- 是否有事件序列数据或可抽取的文本？
- 若只是实体属性查询，不需要事理图谱。

## 4. 低资源学习

### 4.1 知识作为先验

知识图谱在低资源场景的三个作用：
1. 提供语义空间，作为迁移中介（类层次、关系相似性）。
2. 提供推理能力，补足缺失样本（零样本识别）。
3. 提供可解释性（为什么迁移、依据什么）。

### 4.2 方法谱系

| 场景 | 方法 | 关键点 |
|---|---|---|
| 少样本关系预测 | 元学习（MetaR） | 学关系元，不直接学关系向量 |
| 长尾关系抽取 | 关系层次注意力、对抗迁移（wRAN） | 从高资源关系迁移，抑制负迁移 |
| 零样本关系抽取 | 阅读理解式、规则引导、文本生成式 | 用关系描述/规则连接可见与不可见关系 |
| 零样本分类 | KG 类层次 + GNN 特征迁移 | 用本体/WordNet 层次 |
| 终身学习 | 表示对齐、锚点回放 | 防灾难性遗忘 |
| 跨语言 | 跨语言词/关系对齐 | 种子词典 + 匹配 |

### 4.3 落地检查

- 是否有少量种子/标注？没有则不是“低资源”，是“零数据”。
- 迁移源与目标是否相关？负迁移比不迁移更糟。
- 是否报告了低资源子集（低频/新实体/长尾关系）的指标？
- 是否有回退到规则/人工的路径？

## 5. 融合与问答的前沿

### 5.1 融合前沿

| 方向 | 做法 | 适用 | 风险 |
|---|---|---|---|
| 无监督对齐 | 结构与属性互相监督，无需种子 | 无种子、跨语言 | 精度不稳 |
| 多视图对齐 | 名称/结构/属性/描述多视图联合 | 实体信息丰富 | 视图权重难调 |
| 嵌入增强 | 对抗训练削弱度/频率偏差 | 度分布偏差大 | 训练不稳 |
| 大规模对齐 | 分块 + LSH + 分级匹配 | 亿级实体 | 工程复杂 |
| 多模态对齐 | 图像/文本辅助实体匹配 | 多模态实体 | 模态缺失 |

### 5.2 问答数据集（用于对标，不用于验收）

| 数据集 | 特点 | 用途 |
|---|---|---|
| QALD | 多语种、跨数据集、混合问答 | 语义解析/检索 |
| WebQuestions | 通用领域、Freebase | 开放域问答 |
| SimpleQuestions | 单三元组事实 | 简单问答基线 |
| MetaQA | 电影领域、多跳 | 多跳推理 |
| ComplexQuestions | 复杂问题 | 组合推理 |
| WikiMovies | 电影领域 | 领域问答 |

工程提醒：公开集分数不能替代领域验收；领域评估集必须来自真实查询日志。

## 6. 联邦与区块链知识图谱

### 6.1 什么时候需要

适合：
- 多机构/多部门协作，数据不能集中。
- 需要知识确权、溯源、防篡改、贡献计量。
- 需要跨组织共享但保护隐私/知识产权。

不适合：
- 单一组织内部，集中式平台足够。
- 没有多方治理与激励需求。
- 团队没有区块链/分布式系统运维能力。

### 6.2 核心问题

| 问题 | 含义 | 技术手段 |
|---|---|---|
| 价值量化 | 知识被使用产生价值 | 使用频次/传播路径计量 |
| 确权 | 知识归属 | 签名、分布式账本、贡献记录 |
| 溯责 | 错误/恶意知识追责 | 来源链、版本、审计 |
| 可信度量 | 真假与时效 | 多源证据、置信度、时间戳 |
| 隐私 | 数据不共享但可计算 | 联邦学习、差分隐私、可信执行 |

### 6.3 架构要点

- 知识生产层：建模、抽取、校验、融合、补全。
- 知识传播层：价值量化、确权、溯责、可信、激励、隐私。
- 知识消费层：搜索、问答、推理、联邦学习、RPA。

落地建议：先做“逻辑联邦”（保留各图谱独立，按需查询/对齐），再考虑“物理联邦/上链”。不要为了技术概念强行去中心化。

## 7. 前沿模块接入决策

```
要解决的问题是否已有成熟常规方案？
├─ 是 → 先用常规方案，前沿只做增量
└─ 否 → 是否有明确数据与预算？
         ├─ 否 → 先做数据摸底，不上前沿
         └─ 是 → 是否能做小流量 A/B？
                  ├─ 否 → 不做，或只做离线原型
                  └─ 是 → 证明增益 → 扩量 → 保留兜底
```

接入前必须回答：
1. 去掉该模块，基线是多少？
2. 增益是否稳定（多数据集/多时间窗）？
3. 成本（算力、延迟、标注、运维）是否可接受？
4. 失败时的回退路径是什么？
5. 是否引入新的合规/隐私风险？

## 8. 反模式

1. 为“多模态”而多模态，不做模态消融。
2. 把 LLM 当知识库，不做事实校验。
3. 知识注入不看领域匹配，噪声反而降低效果。
4. 事理图谱用实体三元组硬套事件。
5. 低资源场景没有种子，空谈零样本。
6. 单组织内部强行上区块链/联邦。
7. 用公开问答集分数替代领域验收。
8. 前沿模块没有回退方案就上线。
9. 预训练模型不更新，知识过期。
10. 只报最好结果，不报失败案例与成本。
