## 1. 问题空间

知识图谱工程反复解决的五个问题：

1. **表示问题**：用什么结构表达实体、关系、概念、公理与规则？
2. **获取问题**：如何从结构化、半结构化、文本、多模态数据中得到高质量知识？
3. **融合问题**：如何把多源、异构、多语言的同一事物对齐并合并？
4. **推理问题**：如何从已知事实推出未知事实，并保证可解释或可评估？
5. **应用问题**：如何让图谱在搜索、问答、推荐、分析中产生可测收益？

常见误判：
- 把“建图”当成目标，而不是手段。
- 以为三元组能表达所有知识（事件、规则、否定、时序、概率都表达不了）。
- 以为自动抽取可以替代 Schema 与人工校验。
- 以为图数据库能解决所有查询性能问题。
- 以为嵌入模型可以替代符号推理。

## 3. 表示层

### 3.1 三种常用表示模型

| 维度 | 属性图 | RDF(S) | OWL |
|---|---|---|---|
| 基本单元 | 节点、边、属性 | 三元组 | 类、属性、个体、公理 |
| 标准性 | 工业事实标准，非 W3C | W3C 标准 | W3C 标准 |
| 边属性 | 支持 | 需具体化（reification） | 需具体化 |
| 推理 | 弱 | 支持 RDFS 简单推理 | 支持描述逻辑推理 |
| 表达力 | 中 | 中 | 高（按子语言） |
| 工具生态 | 图库/图算法成熟 | 语义网工具成熟 | 本体编辑器/推理机 |
| 适合 | 图结构、路径、分析 | 数据交换、跨组织 | 复杂概念与约束 |

**选择顺序**：
1. 先问“是否需要标准交换/跨组织语义互操作”。是 → RDF。
2. 再问“是否需要类公理、基数、传递/互反/函数关系”。是 → OWL 子语言。
3. 否则默认属性图 + 轻量 Schema；需要时再导出 RDF 视图。

### 3.2 OWL 子语言选择

| 子语言 | 特点 | 适用 | 注意 |
|---|---|---|---|
| OWL 2 EL | 表达力有限，多项式时间推理 | 大规模生物医疗本体 | 不支持全称/析取等 |
| OWL 2 QL | 面向查询重写 | 关系库上的本体查询 | 表达力弱 |
| OWL 2 RL | 规则可实现，复杂度可控 | 需要规则推理的业务图谱 | 不是所有公理都支持 |
| OWL 2 DL | 表达力最强 | 小规模高精度本体 | 推理复杂度高 |

工程建议：v1 用 RDFS + 少量 OWL 2 RL 公理；不要在第一天引入完整 OWL DL。

### 3.3 Schema 设计七步

1. **收集能力问题**：10–20 条，必须来自真实用户。
2. **抽取术语**：名词→类；动词→关系；形容词/数值→属性；时间/地点→限定或实体。
3. **归一**：合并同义词、消除歧义、确定中英文与缩写。
4. **定层次**：isA 树，深度 ≤ 4；避免“其他类”兜底。
5. **定关系**：domain/range、基数、对称/传递/互反/函数性。
6. **定身份**：每类的唯一标识规则（URI、业务主键、组合键）。
7. **定约束与示例**：必填、值域、枚举、时间有效性和反例。

**Schema 质量检查**：
- 每条能力问题都有路径。
- 没有孤立类（无关系、无属性、无实例用途）。
- 没有同义关系重复（如 `author` 与 `writer`）。
- 属性没有被误建为实体类（除非需要独立身份或关系）。
- 每个关系都有 domain/range，且允许的实例类型明确。

### 3.4 表示层反模式

- 把一切塞进一个 `Entity` 类，靠 `type` 字符串区分。
- 把属性值建成实体节点，导致图无限膨胀。
- 关系没有方向或把方向当装饰。
- 用 OWL 表达本可用简单约束表达的东西。
- Schema 没有版本，改一次全量重灌。

## 4. 存储与查询

### 4.1 关系库上的五种方案

| 方案 | 结构 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| 三元组表 | 一张 (s,p,o) 表 | 简单、通用 | 多跳查询 Self-Join 多 | 小规模/原型 |
| 属性表 | 按实体类型建宽表 | Join 少、复用关系库 | 空值多、聚类难 | 类型稳定、属性规整 |
| 垂直划分表 | 每个属性一张 (s,o) 表 | 无空值、无聚类 | 插入跨表、S-O Join 弱 | 属性数量可控 |
| 全索引表 | ID 映射 + 六重索引 | 多维度查询快、压缩好 | 写入/存储成本高 | 查询密集、读多写少 |
| 物化视图/宽表 | 预计算常用路径 | 查询极快 | 更新复杂 | 固定报表/高频查询 |

### 4.2 原生图数据库的核心

- **免索引邻接**：每个节点维护相邻边引用，遍历复杂度正比于邻居数，不随全图规模增长。
- **固定大小记录**：节点/边记录定长，按 ID 直接寻址，节点访问 O(1)。
- **属性分离存储**：属性链与图遍历分离，避免大属性拖慢遍历。
- **结论**：多跳、路径、子图匹配是原生图库的主场；简单点查、聚合统计未必优于关系库。

### 4.3 存储选型决策

```
查询是否以 2+ 跳路径/子图匹配为主？
├─ 是 → 数据规模是否超过单机内存/需要水平扩展？
│        ├─ 是 → 原生图库集群 或 图计算引擎 + 在线图库
│        └─ 否 → 单机原生图库
└─ 否 → 是否已有成熟关系库与运维体系？
         ├─ 是 → 关系库 + 三元组/属性表/垂直划分
         └─ 否 → 按查询形态选：多属性 → 垂直划分；多维索引 → 全索引
```

### 4.4 查询语言

| 语言 | 模型 | 风格 | 适合 |
|---|---|---|---|
| SPARQL | RDF | 描述式，子图匹配 | 语义查询、标准交换、推理 |
| Cypher | 属性图 | 过程式，路径模式 | 工业图应用、可读性强 |
| Gremlin | 属性图 | 过程式，遍历 DSL | 多语言、图遍历 |
| SQL | 关系 | 声明式 | 结构化冷启动、报表 |

工程建议：在线服务用 Cypher/SPARQL；批处理用图计算引擎；不要把复杂图算法硬塞进查询语言。

### 4.5 容量与性能估算

- 三元组存储：按每条 (s,p,o) 的 ID 与索引开销估算，全索引约为原始数据的 3–6 倍。
- 图库：节点/边记录定长，内存主要消耗在索引、缓存与属性。
- 多跳查询：先限制跳数与候选集，再做精确匹配；不要在全图上做无界遍历。
- 写入：图库的边插入通常比关系库贵；高频更新场景优先考虑批量导入与增量合并。

## 5. 知识获取与抽取

### 5.1 任务分解

```
结构化数据 → 映射（R2RML/自定义）→ 实体/三元组
半结构化数据 → 解析（表格/列表/信息框）→ 实体/属性
文本 → NER → 关系抽取 → 属性补全 → 概念抽取 → 事件抽取
多模态 → 实体识别/场景图 → 实体链接 → 关系补充
```

原则：先结构化冷启动，再文本补全；先高频关系，再长尾关系；先抽取式，再生成式。

### 5.2 实体识别

| 方法 | 数据需求 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| 词典/规则 | 少量 | 精准、可解释 | 覆盖窄、维护贵 | 领域术语稳定 |
| HMM | 标注语料 | 简单、可解释 | 特征独立假设强 | 教学/基线 |
| CRF | 标注语料 | 捕获标签依赖 | 需特征工程 | 中等规模 |
| BiLSTM-CRF | 较多标注 | 自动特征、上下文 | 训练成本 | 通用 NER |
| BERT/Transformer | 大量标注/预训练 | 效果好 | 算力、可解释性 | 高精度场景 |

关键设计：
- 标签体系越细，标注成本越高；先用粗粒度，再按错误分析细化。
- 中文要注意分词、嵌套实体、简称与别名。
- 领域词典与模型结合，通常比纯模型更稳。

### 5.3 关系抽取

| 方法 | 数据需求 | 优点 | 缺点 |
|---|---|---|---|
| 触发词/依存模板 | 语言学规则 | 高精度、可解释 | 低召回、难迁移 |
| 特征工程 + 分类器 | 标注语料 | 可控 | 特征成本高 |
| 核函数 | 标注语料 | 自动特征 | 语义比较浅、预处理依赖 |
| CNN/PCNN | 较多标注 | 端到端、位置感知 | 长依赖弱 |
| BiLSTM + Attention | 较多标注 | 长依赖、可解释注意力 | 训练慢 |
| BERT 微调 | 大量标注/预训练 | 效果好 | 成本高 |
| 联合抽取 | 标注语料 | 减少误差传播 | 结构复杂 |

**远程监督的四个降噪手段**（来自深度学习书的方法谱系）：
1. **句级选择性注意力**：同一实体对的多句组成 bag，学习每句权重，降低噪声句影响。
2. **关系层次注意力**：利用关系之间的层次结构，顶层共享长尾关系训练信号。
3. **多语言/对抗训练**：利用多语言一致性与互补性，学习语言不变特征。
4. **图谱—文本互注意力**：图谱表示与文本表示互相指导，联合降噪。

**远程监督落地检查**：
- 是否有多实例 bag 聚合，而不是一句一标？
- 是否报告了 bag 级与句级指标？
- 是否有至少 5% 人工抽检？
- 是否对长尾关系单独评估？
- 是否处理了实体对多关系（一个句子可能对应多个关系）？

### 5.4 属性补全

| 类型 | 机制 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| 抽取式 | 从输入文本选片段 | 可解释、准确 | 只能选文中出现的值 | 属性值常在文本中 |
| 生成式 | 端到端生成 | 可产生未出现值 | 不可解释、易幻觉 | 高频可枚举属性 |
| 分类式 | 属性值视为类别 | 适合枚举属性 | 值域大时不可行 | 性别、类别等 |

工程建议：优先抽取式；生成式只用于低风险、可校验的属性；关键属性必须人工复核。

### 5.5 概念抽取

| 方法 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| Hearst 模板 | 高精度、简单 | 覆盖窄 | 通用 isA |
| Bootstrapping | 半自动扩展 | 语义漂移 | 有种子概念 |
| 百科/信息框 | 质量较高 | 依赖半结构化数据 | 有百科来源 |
| 序列标注 | 可大规模 | 需标注 | 领域概念多 |

语义漂移控制：限制迭代次数、类型过滤、多模板耦合、人工审核新增概念。

### 5.6 事件抽取

- 任务分解：触发词识别与事件分类 → 论元检测 → 论元角色分类。
- 方法谱系：模式匹配（高精度低召回）→ 特征/结构联合模型（减少误差传播）→ 神经网络（DMCNN 两阶段）→ 预训练/联合结构预测。
- 难点：标注成本高、论元依赖复杂、中文无显式分词、跨句/文档级事件。
- 落地建议：先定义事件 Schema（类型、触发词、角色、必填论元），再做抽取；事件与实体图谱通过实体链接关联。

### 5.7 低资源抽取

| 场景 | 方法 | 关键点 |
|---|---|---|
| 少样本 | 原型网络、元学习（MetaR） | 用关系元学习，不直接学关系向量 |
| 长尾关系 | 关系层次注意力、对抗迁移（wRAN） | 从高资源关系迁移，抑制负迁移 |
| 零样本 | 阅读理解式、规则引导、文本生成式 | 利用关系描述/规则建立可见与不可见关系联系 |
| 终身学习 | 表示对齐、回放锚点 | 防止灾难性遗忘 |

### 5.8 标注与质检

- 先写标注规范：标签定义、边界规则、歧义处理、反例。
- 双人标注 10% 样本，计算一致率；不一致处仲裁并回写规范。
- 抽检分层：按关系类型、来源、置信度分层，不要只抽高置信度。
- 记录错误类型：边界错误、类型错误、漏标、关系方向错误、噪声句。
- 模型置信度不是准确率；必须用抽检校准。

## 6. 知识表示学习

### 6.1 平移模型族

| 模型 | 核心假设 | 评分函数（概念） | 解决的问题 | 遗留问题 |
|---|---|---|---|---|
| TransE | h + r ≈ t | ‖h+r−t‖ | 高效、可扩展 | 一对多/多对多、对称关系 |
| TransH | 实体投影到关系超平面 | ‖h⊥+r−t⊥‖ | 部分复杂关系 | 投影表达能力有限 |
| TransR | 每关系一个投影矩阵 | ‖M_r h + r − M_r t‖ | 实体在不同关系下语义不同 | 参数多、训练贵 |
| CTransR | 关系内再聚类 | 每簇一个 r_c，加约束 | 同一关系下的子关系差异 | 聚类质量依赖数据 |
| TransD | 动态映射矩阵 | 头尾各自投影 | 参数效率 | 仍受平移假设限制 |
| RotatE | 关系是复空间旋转 | t ≈ h ∘ r，|r|=1 | 对称/逆/组合关系 | 训练技巧要求高 |
| DistMult | 双线性对角 | hᵀ diag(r) t | 简单有效 | 只能建模对称关系 |
| ComplEx | 复空间双线性 | Re(hᵀ diag(r) conj(t)) | 非对称关系 | 参数与调参 |
| HolE/RESCAL | 张量/循环相关 | 张量分解 | 表达力强 | 计算复杂 |

**选择起点**：
- 基线：TransE（快、可解释假设简单）。
- 一对多/多对多明显：TransR 或 KR-EAR。
- 对称/逆/组合关系多：RotatE 或 ComplEx。
- 需要路径证据：PTransE。
- 稀疏/新实体：DKRL/TKRL/IKRL 或 MetaR。

### 6.2 结构增强

- **PTransE**：在直接关系之外加入多步路径；路径可靠性用资源分配（PCRA）估计；路径表示可用加法、乘法或 RNN；通常 2–3 步足够。
- **KR-EAR**：把关系分为“属性”（尾实体为抽象值）与“关系”（头尾均为实体）；属性用分类模型，关系用平移模型；可建模属性相关性。
- **CTransR**：对同一关系的实体对按 h−t 聚类，每簇单独关系向量，缓解关系内部语义多样。

### 6.3 外部信息融合

| 模型 | 外部信息 | 融合方式 | 适用 |
|---|---|---|---|
| DKRL | 实体描述文本 | 文本编码器（CBOW/CNN）+ 结构表示联合能量 | 零样本、描述丰富 |
| TKRL | 实体层次类型 | 类型特化投影矩阵 + 层次编码器 | 类型体系完善 |
| IKRL | 实体图像 | 图像编码器 + 多图像注意力 | 多模态、图像丰富 |
| 本体嵌入 | TBox 概念/公理 | 概念映射为球/区域，公理转为约束 | 概念层推理 |

工程提醒：外部信息不是越多越好；先验证信息覆盖率与噪声，再做融合。

### 6.4 训练与评测协议

- **负采样**：随机替换头或尾；对一对多关系用伯努利采样，避免假阴性偏差。
- **损失**：最大间隔（margin ranking）或交叉熵；margin 常从 {1,2,4} 起调。
- **超参数起点**：维度 50–100；学习率 0.001；batch 480–4800；训练 500–1000 轮；L1 距离常用于平移模型。
- **评测**：
  - 链接预测：Mean Rank（越低越好）、MRR、Hit@1/3/10（越高越好）。
  - **必须过滤**：排序前去掉其他真实三元组，否则指标虚低/虚高都不可比。
  - 三元组分类：按关系设阈值，报告准确率与阈值选择方法。
- **诊断切片**：按关系基数（1-1/1-N/N-1/N-N）、实体频次（头部/长尾）、是否新实体分别报告。

## 7. 知识融合

### 7.1 本体匹配

流程：
1. 规范化：空白、大小写、变音符号、标点、缩写。
2. 术语相似度：编辑距离、汉明距离、最长公共子串、Dice、Jaccard、TF-IDF。
3. 语言方法：词形归一、WordNet 同义/上下位。
4. 结构方法：邻居、属性、层次路径；虚拟文档把概念自身描述 + 邻居文档化。
5. 大规模：先分块（哈希、排序邻居、LSH），再块内匹配。
6. 人工审核：高风险映射必须人审。

### 7.2 实体对齐

流程：
1. **分块**：避免 O(M×N)；按名称首字母、LSH、属性桶、邻居排序。
2. **特征/嵌入**：名称、属性、结构、类型、描述、图像。
3. **种子对齐**：人工或高置信规则产生种子。
4. **联合嵌入**：参数共享、平移映射或线性映射，把两个图谱放到同一空间。
5. **迭代对齐**：新对齐实体加入种子；硬对齐（共享嵌入）易错误传播，优先软对齐（按可靠度加权）。
6. **阈值与人工复核**：高于高阈值自动接受，中间区间人审，低于低阈值拒绝。

**可靠性评分**：可用 sigmoid(θ − 距离) 形式把距离转成置信度；新对齐实体按置信度加权，而不是一刀切。

### 7.3 冲突裁决

| 冲突 | 裁决规则 |
|---|---|
| 同一实体多个名称 | 选权威源 + 保留别名 |
| 属性值不一致 | 按来源可信度、时间、证据数投票 |
| 关系方向不一致 | 以 Schema 的 domain/range 为准 |
| 类型不一致 | 允许一个实体多类型；互斥类型需人工裁决 |
| 时间有效性冲突 | 采用双时间（有效时间/记录时间）建模 |

合并原则：逻辑合并优先，物理合并可回滚；保存来源、时间、置信度、合并日志。

## 8. 推理与补全

### 8.1 推理类型

| 类型 | 方向 | 例子 | 适合技术 |
|---|---|---|---|
| 演绎 | 规则 + 事实 → 结论 | 父子关系传递 | OWL/Datalog/产生式 |
| 归纳 | 事实 → 规则 | 从路径学规则 | PRA/AMIE/NeuralLP |
| 溯因 | 现象 + 规则 → 原因 | 草地湿→可能下雨 | 事理图谱/概率模型 |
| 类比 | 相似实体 → 迁移属性 | A 类同 B 类 | 嵌入/迁移学习 |

### 8.2 符号推理

| 技术 | 表达力 | 可解释 | 规模 | 适用 |
|---|---|---|---|---|
| OWL 本体推理 | 高 | 强 | 中 | 概念包含、实例检测 |
| Datalog | 中高 | 强 | 中 | 递归规则、路径 |
| 产生式 + Rete | 中 | 强 | 小中 | 业务规则、专家系统 |

注意：符号推理要求知识精确；开放世界假设下“查不到”不等于“假”。

### 8.3 规则学习

- **PRA**：把路径类型当特征，学习权重；随机游走控制路径爆炸；输出可读路径规则。
- **AMIE**：从空体规则开始，通过悬挂边/实例边/闭合边扩展；用支持度、头覆盖度、置信度、PCA 置信度筛选。
- **NeuralLP/DRUM**：把规则学习变成可微的矩阵算子组合；可学习变长规则；NeuralLP-N 支持数值比较与否定。
- **IterE**：嵌入学习 → 公理归纳 → 公理注入，迭代提升稀疏实体表示。

规则学习落地：
- 先限定规则长度（≤ 3）与谓词范围。
- 用支持度阈值剪枝，再人工审核高影响规则。
- 规则与嵌入结合，不要单独依赖规则挖掘。

### 8.4 嵌入推理与多跳

| 需求 | 模型/方法 | 说明 |
|---|---|---|
| 基础链接预测 | TransE/TransR/RotatE | 先跑基线，再看切片 |
| 多跳逻辑查询 | BetaE | 把逻辑操作映射为概率分布变换 |
| 路径搜索式多跳 | MINERVA 等强化学习 | 在图上逐步游走找答案 |
| 稀疏/长尾关系 | wRAN、MetaR | 迁移/元学习 |
| 规则 + 嵌入 | IterE | 互增强 |
| 图结构丰富 | R-GCN/CompGCN | 聚合邻居，需解码器 |
| 概率图 + GNN | ExpressGNN | 加速马尔可夫逻辑网络推理 |

### 8.5 推理选型决策树

```
是否需要给出严格证明/审计链？
├─ 是 → 规则是否稳定且可人工维护？
│        ├─ 是 → OWL/Datalog/产生式
│        └─ 否 → 规则学习（PRA/AMIE）+ 人工审核
└─ 否 → 是否主要是缺失三元组补全？
         ├─ 是 → 训练数据是否充足？
         │        ├─ 是 → 嵌入模型（TransE/TransR/RotatE）
         │        └─ 否 → 路径/外部信息/元学习（PTransE/DKRL/MetaR）
         └─ 否 → 是否多跳逻辑查询？
                  ├─ 是 → BetaE/强化学习游走/查询分解
                  └─ 否 → 图结构是否丰富？
                           ├─ 是 → GNN（R-GCN/CompGCN）
                           └─ 否 → 回到符号/规则或补充数据
```

### 8.6 推理评测

- 链接预测：过滤式 MR/MRR/Hit@n；按关系基数与频次切片。
- 规则质量：支持度、覆盖率、置信度、人工 precision。
- 多跳问答：答案准确率、路径准确率、可解释率。
- 高风险场景：人工复核率、误报成本、漏报成本。

## 9. 应用层

### 9.1 KGQA 四范式

| 范式 | 流程 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| 模板 | 问句 → 模板匹配 → 实例化 → 查询 | 快、准、可控 | 模板维护贵、覆盖窄 | 固定业务问句 |
| 语义解析 | 问句 → 逻辑表达式 → 查询 | 可组合、可解释 | 词典/对齐难 | 复杂但结构化的问题 |

混合策略（生产推荐）：
1. 高频固定问题走模板，保证准确与延迟。
2. 复杂问题走语义解析/查询图。
3. 开放问题走检索排序。
4. 全部答案附来源与置信度；低置信度转人工。

| 实体分类 | 关系与类型作为上下文 | 知识注意力 |
| 信息检索 | 实体语义增强查询/文档表示 | 实体链接质量 |
| 风控/反欺诈 | 关系网络、团伙发现、路径证据 | 可解释与审计 |
| 大数据分析 | 把分析问题转为图查询/图算法 | Schema 与查询设计 |

## 10. 跨书共识与冲突

### 10.1 共识（作为核心规则）

1. Schema/本体是知识图谱的基础工作，不能跳过。
2. 知识图谱是系统工程，不是单一模型。
3. 结构化数据冷启动 + 自动抽取 + 人工校验是主流构建路线。
4. 符号表示与向量表示互补，不是替代关系。
5. 稀疏与长尾是核心难题，需要专门方法。
6. 评估必须绑定下游任务，不能只看图谱规模或公开集分数。

### 10.2 冲突与条件分支

| 冲突点 | 观点 A（导论） | 观点 B（深度学习书） | 适用条件 | Skill 采用方式 |
|---|---|---|---|---|
| 逻辑严格性 | 为规模可降低表示严格性，常用属性图 | 强调结构化知识与精确表示 | 早期构建/图分析 vs 推理/审计 | 分阶段：先属性图，后 RDF/OWL 子集 |
| 推理路线 | 符号精确但难扩展；表示学习高效但不可解释 | 表示学习 + 规则学习互补 | 高风险 vs 大规模 | 混合推理，按风险分级 |
| 图神经网络 | 图结构丰富时才适合 | 更关注 KRL 的语义建模 | 稀疏 vs 稠密 | 先测结构密度，再决定 |
| 实体对齐 | 字符串/结构/表示学习多路线 | KRL + 种子 + 迭代对齐 | 有无种子、规模大小 | 有种子用迭代嵌入；无种子先分块+规则 |
| 远程监督 | 可大规模但噪声大 | 用注意力/多语言/互注意力降噪 | 数据规模 vs 精度 | 默认降噪，抽检不达标不加量 |
| QA 路线 | 模板/语义解析/检索排序各有优劣 | 深度学习增强解析与排序 | 问题复杂度/标注量 | 混合架构，模板兜底 |

## 11. 原创示例

### 示例 A：医疗器械不良事件监测图谱

**能力问题**
1. 某型号器械在某时间段内是否出现某类不良事件的聚集？
2. 同一患者使用多个器械时，哪些组合的风险更高？
3. 某批次器械涉及哪些医院、哪些报告、是否已召回？
4. 某厂商的哪些型号在近 12 个月事件率上升？

**Schema（属性图）**
- 类：器械型号、器械批次、厂商、患者（匿名 ID）、医院、不良事件、报告、时间、身体部位、严重程度。
- 关系：`使用(患者,器械批次)`、`发生(患者,事件)`、`报告(医院,事件)`、`属于(批次,型号)`、`生产(厂商,型号)`、`召回(厂商,批次)`、`涉及部位(事件,部位)`。
- 身份规则：器械用 UDI；批次用厂商+批号；事件用报告 ID；患者用院内匿名 ID。
- 约束：事件必须有时间与严重程度；批次必须关联型号；报告必须关联医院。

**构建**
- 结构化报告冷启动（字段映射）。
- 文本叙述做属性补全与事件论元抽取。
- 器械/厂商名称跨源对齐（NMPA、医院、厂商官网）。

**推理**
- 规则：同批次 + 同医院 + 时间窗 + 同类事件 → 聚集信号。
- 嵌入：仅用于候选扩展，不直接产出监管结论。
- 高风险结论必须人工复核并给出证据链（报告、时间、批次、医院）。

**评估**
- 信号 precision/recall、预警提前量、人工复核工作量、误报成本。

**反例**：用 TransE 直接预测“器械-事件”关系并当作监管结论；忽略批次与时间；把厂商别名当成不同实体。

### 示例 B：影视 IP 知识图谱

**能力问题**
1. 某演员参演的作品中，哪些角色之间存在亲属/敌对关系？
2. 某角色在不同改编作品中由哪些演员饰演？
3. 某奖项的历届获奖者与提名者是谁？
4. 某作品的原著、编剧、导演、出品方之间是什么关系？

**Schema（属性图，轻量）**
- 类：作品、人物（演员/导演/编剧）、角色、组织、奖项、改编版本。
- 关系：`饰演(演员,角色)`、`出演(演员,作品)`、`改编自(作品,作品)`、`执导(人物,作品)`、`获奖(作品/人物,奖项)`、`亲属(角色,角色)`。
- 身份规则：作品用平台 ID + 标题年份；人物用权威 ID + 别名；角色用作品+角色名。

**构建**
- 百科信息框冷启动；文本抽取补充关系；跨平台实体对齐（豆瓣/维基/IMDb）。

**应用**
- 搜索：实体卡片 + 关系扩展。
- 问答：模板覆盖高频问题；复杂问题走检索排序。
- 推荐：同演员/同导演/同宇宙路径。

**反例**：把角色与演员混为一类；不做版本区分导致“同一角色不同演员”合并错误。

### 示例 C：供应链风险传播图谱

**能力问题**
1. 某零部件断供会影响哪些整车厂与车型（2–3 跳）？
2. 某地区突发事件会影响哪些供应商与产品？
3. 某供应商的替代供应商有哪些，切换成本如何？
4. 某企业集团的子公司/关联公司是否共享同一风险源？

**Schema**
- 类：供应商、零部件、产品、工厂、地区、事件、企业集团。
- 关系：`供应(供应商,零部件)`、`装配(零部件,产品)`、`生产(工厂,产品)`、`位于(工厂,地区)`、`受影响(事件,地区/供应商)`、`隶属于(供应商,集团)`、`替代(供应商,供应商)`。
- 身份规则：供应商用统一社会信用代码；零部件用物料编码；集团用集团 ID。

**推理**
- 路径查询 + 规则（断供 → 库存耗尽 → 停产）为主。
- 稀疏关系用 PTransE/规则学习补全；图结构丰富时才上 GNN。
- 输出风险路径与证据，不只给风险分数。

**评估**
- 风险路径召回率、平均预警时间、误报率、人工确认成本。

## 12. 失败模式手册

| 症状 | 可能原因 | 诊断 | 修复 |
|---|---|---|---|
| 图谱建了没人用 | 没有任务对齐 | 回看能力问题与查询日志 | 重做 Stage 0/1，删无用本体 |
| 查询很慢 | 存储/查询不匹配 | 基准查询剖析 | 换存储、加索引、限制跳数 |
| 抽取准确率低 | 标签体系/领域漂移/噪声 | 分层错误分析 | 补规范、加规则、领域微调 |
| 召回率低 | Schema 太窄/数据源不足 | 未命中查询聚类 | 扩 Schema、加数据源、开放关系 |
| 对齐错误传播 | 硬对齐/阈值过低 | 审计对齐样本 | 软对齐、提高阈值、回滚 |
| 链接预测虚高 | 未过滤/数据泄漏 | 检查评测协议与切分 | 过滤式评测、时间切分 |
| 稀疏实体效果差 | 只用结构嵌入 | 按频次切片 | DKRL/PTransE/MetaR/规则 |
| 一对多效果差 | TransE 假设不成立 | 按关系基数切片 | TransR/KR-EAR/CTransR |
| 规则维护不动 | 规则过多/冲突 | 规则命中与冲突统计 | 规则挖掘 + 优先级 + 退役机制 |
| QA 答非所问 | 实体链接/类型检查缺失 | 逐段审计流水线 | 加强实体链接、类型约束、兜底 |
| 知识过期 | 无时间戳/版本 | 抽查时效 | 双时间建模、更新流水线 |
| LLM 幻觉写回 | 无校验 | 溯源审计 | 图谱校验、置信度阈值、人工复核 |
| 融合后实体爆炸 | 过度拆分/合并 | 实体频次与 sameAs 审计 | 身份规则、合并阈值、人工裁决 |
