# 知识图谱工程质量 Rubric

用于方案评审、阶段验收与 Agent 自检。所有分数按 0–3 打分，交付阈值见文末。

---

## 1. 总评分表

| 维度 | 0 分 | 1 分 | 2 分 | 3 分 |
|---|---|---|---|---|
| 任务对齐 | 无下游任务 | 有目标无指标 | 有指标与查询样例 | 指标、基线、验收标准齐全，并有“不做什么” |
| Schema | 无 Schema | 只有类名 | 类/关系/属性/值域齐全 | 能力问题覆盖矩阵、身份规则、版本策略齐全 |
| 数据质量 | 无抽检 | 只报模型指标 | 有分层抽样与错误分类 | 双人标注、一致率、置信度校准、来源溯源 |
| 融合 | 未处理多源 | 只做字符串匹配 | 分块 + 多特征 + 人工审核 | 迭代对齐 + 冲突裁决 + 可回滚 |
| 推理 | 无推理 | 只用模型打分 | 符号/向量按场景选型 | 混合推理 + 证据链 + 高风险复核 |
| 可解释 | 无来源 | 只有答案 | 有路径/规则/来源 | 可审计推理链 + 置信度 + 时间有效性 |
| 工程 | 脚本堆叠 | 有 ETL | 有版本、监控、回滚 | 有 SLA、容量规划、权限与成本模型 |
| 评估 | 无评估 | 只用公开集 | 有领域评估集 | 端到端 + 分阶段 + 错误归因闭环 |

**总分 24 分。交付阈值：≥ 18 分；任务对齐、Schema、数据质量、评估均不得低于 2 分。**

## 2. 阶段闸门

### G0 任务适配闸门

| 检查项 | 通过标准 | 不通过的处理 |
|---|---|---|
| 关系中心 | 任务核心是实体关系，不是单文本匹配 | 改 RAG/搜索 |
| 多跳需求 | 至少 30% 查询需要 2+ 跳或聚合/比较 | 降级为表格/搜索 |
| 结构化收益 | 结构化后精度/速度/可解释性有明确提升 | 写清收益假设并做小样本验证 |
| 数据可得 | 关键实体/关系有稳定来源 | 缩小范围或先做数据摸底 |
| 可维护 | 有 Schema/标注/质量负责人 | 不启动，或只做只读原型 |

### G1 Schema 闸门

| 检查项 | 通过标准 |
|---|---|
| 能力问题覆盖 | 100% 的 CQ 能映射到查询路径 |
| 类层次 | 深度 ≤ 4；无“其他类”兜底 |
| 关系定义 | 每个关系有 domain/range、方向、基数 |
| 身份规则 | 每个类有唯一标识规则 |
| 命名规范 | 同义关系已合并；命名一致 |
| 属性 vs 关系 | 属性未被误建为实体类 |
| 示例与反例 | 每类至少 3 条正例、1 条反例 |

### G2 表示与存储闸门

| 检查项 | 通过标准 |
|---|---|
| 表示选型 | 有明确理由，且与查询形态匹配 |
| 存储选型 | 有 3 条基准查询的延迟与实现复杂度记录 |
| 容量估算 | 实体/边/属性/索引的存储与增长估算 |
| 写入与更新 | 批量导入、增量更新、删除策略明确 |
| 备份与回滚 | 有快照/导出/回滚方案 |
| 查询语言 | 团队能维护；复杂查询有示例 |

### G3 抽取闸门

| 检查项 | 通过标准 |
|---|---|
| 标签体系 | 有定义、边界规则、歧义处理、反例 |
| 抽检 | 每批 100–300 条，分层抽样 |
| 一致率 | 双人标注 10%，一致率 ≥ 0.85（或明确仲裁机制） |
| 指标 | 准确率、召回率、F1 按关系类型分别报告 |
| 错误分析 | 错误类型分布与修复计划 |
| 置信度 | 模型分数经过抽检校准，不是裸分数 |
| 长尾 | 长尾关系单独评估并有策略 |

**建议指标（按用途）**：

| 用途 | 关系抽取准确率 | 关系抽取召回率 | 实体识别 F1 |
|---|---|---|---|
| 搜索/问答 | ≥ 0.90 | ≥ 0.70 | ≥ 0.85 |
| 分析/风控 | ≥ 0.85 | ≥ 0.80 | ≥ 0.85 |
| 探索/冷启动 | ≥ 0.75 | ≥ 0.60 | ≥ 0.75 |

指标不是定律；高风险场景应提高准确率要求并增加人工复核。

### G4 融合闸门

| 检查项 | 通过标准 |
|---|---|
| 分块 | 有分块策略，避免 O(M×N) 全量比较 |
| 对齐 | 抽检准确率 ≥ 0.95；召回率按业务定 |
| 冲突 | 有裁决规则与记录 |
| 回滚 | 合并可回滚；保留来源与版本 |
| 大规模 | 有 LSH/分块/并行方案与容量测试 |

### G5 推理闸门

| 检查项 | 通过标准 |
|---|---|
| 选型 | 与查询类型、规模、可解释性要求匹配 |
| 评测 | 过滤式 MR/MRR/Hit@n；按关系基数与频次切片 |
| 规则 | 规则有支持度、覆盖率、人工 precision |
| 高风险 | 有证据链、置信度阈值、人工复核 |
| 稀疏 | 稀疏实体/长尾关系有专门策略 |

### G6 应用闸门

| 检查项 | 通过标准 |
|---|---|
| 评估集 | 真实问题 ≥ 200 条，覆盖全部 CQ 类型 |
| 基线 | 有非图谱基线（搜索/规则/LLM） |
| 指标 | 答案准确率、覆盖率、延迟、可解释率、人工接管率 |
| 错误归因 | 错误能定位到 Schema/抽取/融合/推理/应用层 |
| 兜底 | 低置信度有降级路径 |

### G7 运维闸门

| 检查项 | 通过标准 |
|---|---|
| 监控 | 数据量、查询延迟、错误率、未命中率、抽取置信度分布 |
| 版本 | Schema、数据、模型、规则均有版本 |
| 回滚 | 任一次发布可回滚 |
| 权限 | 读写、敏感字段、审计日志 |
| 成本 | 存储、算力、标注、人力成本可估算 |

## 3. 指标定义与口径

### 3.1 链接预测

- **MR（Mean Rank）**：正确实体在候选排序中的平均名次，越低越好。
- **MRR（Mean Reciprocal Rank）**：正确实体名次倒数的平均值，越高越好。
- **Hit@n**：正确实体排名在前 n 的比例，越高越好。
- **过滤式（filtered）**：排序前移除其他真实三元组；报告时必须注明 raw/filtered。
- **切片**：按 1-1/1-N/N-1/N-N、头/尾实体频次、是否新实体分别报告。

### 3.2 三元组分类

- 准确率、precision/recall/F1；按关系设阈值。
- 阈值必须在验证集上选，不能看测试集调。
- 报告正负样本比例与负采样方法。

### 3.3 抽取

- 实体级：precision/recall/F1（按类型）。
- 关系级：句级与 bag 级分别报告；bag 级更接近远程监督真实使用。
- 属性级：值准确率、覆盖率、可解释率。
- 事件级：触发词分类 F1、论元角色 F1、事件级 F1。

### 3.4 融合

- 对齐 precision/recall/F1；按实体频次与类型切片。
- 分块召回率（blocking recall）：候选块是否包含正确配对。
- 合并错误率与回滚耗时。

### 3.5 端到端

- 答案准确率（exact match / 语义等价）。
- 覆盖率（可回答问题比例）。
- 延迟 P50/P95。
- 可解释率（有来源/路径/规则的比例）。
- 人工接管率与单次接管成本。

## 5. 常见“假达标”

- 用公开数据集分数代替领域验收。
- 只报准确率，不报覆盖率与召回率。
- 链接预测不注明 raw/filtered，或数据切分有泄漏。
- 对齐只报 precision，不报 recall。
- 抽取只抽高置信度样本。
- QA 只评估可回答问题，忽略拒答与人工接管。
- 用“图谱规模”代替“任务收益”。
- 用 LLM 生成答案但不做事实校验。

出现任一项，相关维度最高记 1 分。
