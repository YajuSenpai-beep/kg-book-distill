# Skill 决策盲测报告（首轮单模型）

> 后续已用 4 个模型复测，见 `backtest-multimodel.md`。本文件保留首轮单模型记录。

日期：2026-11-22
对象：`kg-engineering` Skill
用例：20 条（`backtest-questions.jsonl`，仅 ID + 问题，不含期望答案）

## 方法

1. 另起一个**不带本会话上下文**的 Agent，只允许读取 `SKILL.md` 与其 `references/`。
2. 明确禁止读取 `decision-cases.jsonl` 和本报告，保证盲测。
3. 每题输出：结论、2–3 条动作、依据文件/小节、置信度。
4. 由主会话按 `decision-cases.jsonl` 的 `expected` 做语义评分，不要求逐字匹配。

评分口径：

| 分 | 标准 |
|---:|---|
| 2 | 决策分支正确，且 expected 的关键概念全部出现 |
| 1 | 决策分支正确，但缺少一个关键概念或机制解释 |
| 0 | 分支错误，或答成 Skill 未覆盖 |

## 失败与改进

**D08（1 分）**：结论正确（“不默认上图数据库，按多跳查询决定”），也提到关系库与多跳，但没有解释原生图库的关键机制“免索引邻接”，因此理由链不完整。

改进：已在 `SKILL.md` Stage 2 存储选型表写明“免索引邻接”，但该表述在回答中没有被引用。后续可把“为什么快”固定成一句检查项：**“选原生图库必须能说出免索引邻接与遍历复杂度；否则只是换了个存储。”**

这不是知识缺失，而是检索/表述未命中；属于可修复的提示词问题。

## 这个报告能证明什么

- Agent 在只看 Skill 的情况下，20 个场景的分支选择全部正确。
- 19/20 能同时给出 expected 的关键概念与可执行动作。
- 路由表足以让 Agent 自行找到对应 reference。

## 不能证明什么

- **单次运行、单模型**：没有重复采样，也没有换模型交叉验证。
- **评分者不是独立人类专家**：语义评分由主会话完成，存在同源偏差。
- **用例是合成的**：20 条覆盖典型分支，不等于真实用户分布。
- **未测多轮澄清**：真实项目里信息缺失、用户改需求、预算约束都未纳入。
- **未测数值阈值**：如“准确率 ≥0.85”是否合理，需要领域数据验证。
