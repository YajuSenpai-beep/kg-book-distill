# Skill 决策用例

20 条“场景 → 期望规则”的 smoke 用例，覆盖 GNN 适用性、复杂关系、分块、高风险推理、远程监督、零样本、多跳、存储选型、对齐、KGQA、知识注入、多模态、区块链、义原、事件、链接预测、抽取质量。

## 运行

```bash
cd scripts
python skill_rule_check.py ../evals/decision-cases.jsonl
```

当前结果：规则存在性 20/20 通过；另有一次盲测决策 20/20、关键概念 19/20，见下方“盲测结果”。

## 盲测评分脚本

```bash
python grade_backtest.py answers-haiku.json --md grade-haiku.md
```

只统计 expected 概念覆盖，不判断分支对错；同义表达在脚本的 `SYNONYMS` 中维护。分支正确性仍需人工/LLM 复核。

## 这个检查能证明什么

- 期望的决策规则确实写进了对应 reference（关键词存在）。
- 规则文件没有在重构中丢失。

## 不能证明什么

- 不能证明 Agent 在真实对话中会选对分支。
- 不能证明阈值/条件在真实数据上最优。
- 关键词存在不等于表述无歧义。

## 复现二次盲测

1. 把 `backtest-questions.jsonl` 交给一个新的、只加载本 Skill 的 Agent。
2. 禁止其读取 `decision-cases.jsonl` 与本报告。
3. 记录：选了什么分支、引用了哪条规则、是否给出反例/边界。
4. 用 `expected` 作最低标准，按 0–2 评分；低于 1.5 的用例回补规则或改写触发条件。
5. 换模型或重复 3 次，检查稳定性。

单次盲测只说明“这条路径走得通”，不说明“所有模型、所有问法都稳定”。
